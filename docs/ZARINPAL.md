# راه‌اندازی و عیب‌یابی زرین‌پال در SimPars (API v4)

مرجع: https://www.zarinpal.com/docs/paymentGateway/connectToGateway

## جریان پرداخت
1. **فاکتور اتوماتیک**: ربات با `request.json` (مبلغ به ریال، `currency=IRR`، `metadata.order_id` و در صورت وجود `metadata.mobile`) یک `authority` می‌گیرد.
2. کاربر از `https://pay.prostoreshop.site/pay/<authority>` (دامنه خودمان، برای Referer معتبر و جلوگیری از خطای -18) به `StartPay` می‌رود.
3. زرین‌پال کاربر را به `https://pay.prostoreshop.site/zarinpal/callback?Authority=...&Status=OK|NOK` برمی‌گرداند. فقط در `OK` متد `verify.json` صدا زده می‌شود. کد `100` = تایید اول، `101` = قبلاً تایید شده.
4. **پرداخت اتوماتیک**: اگر کاربر به سایت برنگردد، worker هر ۶۰ ثانیه با `unVerified.json` و `inquiry.json` (فقط برای استعلام) تراکنش‌های در انتظار را پیدا و با `verify` تایید می‌کند؛ سپس کیف پول شارژ یا شماره مستقیماً تحویل می‌شود.

## تنظیمات لازم
| مورد | مقدار |
|---|---|
| `BASE_URL` در `.env` | `https://pay.prostoreshop.site` (بدون `/` آخر) |
| دامنه درگاه در پنل زرین‌پال | `prostoreshop.site` یا `pay.prostoreshop.site` |
| Callback در پنل ربات | خالی بگذار؛ همیشه `BASE_URL/zarinpal/callback` ساخته می‌شود |
| Merchant ID | ۳۶ کاراکتری، همان ترمینالی که دامنه بالا رویش ثبت است |
| حالت تست | در محیط واقعی خاموش |

## خطاهای رایج
| کد | علت | راه حل |
|---|---|---|
| -9 | مرچنت/مبلغ/توضیحات/Callback نامعتبر | مرچنت و `BASE_URL` را چک کن |
| -10 | مرچنت یا IP سرور غلط | IP سرور را در پنل زرین‌پال ثبت کن |
| -14 | دامنه Callback با دامنه درگاه یکی نیست | `BASE_URL` را دقیقاً دامنه ثبت‌شده بگذار |
| -18 | Referer نامعتبر | لینک را فقط از دکمه ربات (صفحه `/pay/...`) باز کن |
| -51 | پرداخت ناموفق | کاربر پرداخت را کامل نکرده |
| -54 | اتوریتی نامعتبر | فاکتور جدید بساز |

**نکته امنیتی:** Merchant ID را فقط در پنل مدیریت ربات وارد کن و داخل GitHub قرار نده.
